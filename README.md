# 人效提升作战沙盘（Android）

一款面向现场 IE、班组长、工艺工程师的 Android 手机/平板小程序。输入现场测定数据后，自动生成**人效提升作战沙盘**、**布局调整方案**、**人员调配方案**和**人效提升方案**。

## 功能模块

| 模块 | 说明 |
|------|------|
| 数据录入 | 维护**工作时段**（可编辑，默认三段 `8:10-10:00 / 10:15-11:30 / 13:00-19:00`，自动累加为日可用时间）、**日需求（台/日）** 等全局参数，以及每道工序的「单件作业时间、当前人数、工位数、工种类型、走动时间、工位坐标、改善后单件/人数」 |
| **调度大屏** | **生产调度核心页**：顶部「日产台数」场景选择器（预设 1/2/3/5/10/20/50/80 台/日 + 步进 + **手动输入任意正整数**），实时重算客户节拍、需要人数、最少人数、瓶颈、支援方案；Excel 式作战图矩阵 + 自动支援卡片。宽屏自动切换为左侧导航栏，适合车间大屏投影 |
| 作战沙盘 | KPI 卡片（产线节拍、平衡率、瓶颈工序、预计日产量）+ 节拍/负荷率/人员差异可视化 |
| **作战图** | **Excel 式横向矩阵 + 工序人员调整路线图**：客户节拍/日产台数、协作/支援路线图（箭头标注「N人」）、单人单台时间、N 台时间、日可用时间、差异时间、需要人数、人员配置；底部列出**每天支援时段**（含 20% 弹性缓冲）的支援卡片 |
| **改善对比** | **改善前/改善后** 指标对比（总人员、产线节拍、平衡率、日产量、标准工时、最少人数），逐项标注改善方向；工序级时间/人数对比表，可分享 |
| 布局调整 | 工位画布 + 布局建议（高负荷工序靠近、物流动线、区域集中/隔离） |
| 人员调配 | 当前 vs 理想人数对比、人员差异、工序级调配建议 |
| 提升方案 | 自动生成瓶颈增员、冗余再分配、合并短工序、平衡率提升等综合方案，支持分享报告 |

> **面向大屏生产调度**：把平板/手机通过 HDMI 或无线投屏接入车间大屏，打开「调度大屏」页，切换日产台数即可作为实时排产看板。

## 核心算法

### 基础指标
- **工序节拍** = 单件作业时间 / 当前人数
- **产线节拍** = max(工序节拍)
- **客户节拍 Takt** = 日可用时间 / 日需求（即日产台数）
- **平衡率** = Σ单件时间 / (产线节拍 × 工序数) × 100%
- **理想人数** = ceil(单件时间 / 客户节拍)
- **人员差异** = 当前人数 - 理想人数

### 生产调度人员匹配（调度大屏 / 作战图核心）
- **需要人数** = ceil(单件时间 × 日产台数 / 日可用时间) —— 即「差异时间 = 日可用 − 单件×日产」为正时 1 人即可满足，为负则需增人
- **差异时间** = 日可用时间 − 单件时间 × 日产台数（单人日负荷：正=富余可调出，负=不足需支援）
- **N 台时间**（仅作信息展示）= 单人看 m 台周期 = 单件时间 / m + (m − 1) × 走动时间，用于评估一人多机可行性
- 切换「日产台数」场景时，Takt 与需要人数实时重算，自动给出不同产量下的最少人员配置

### 自动支援调配
- 按**工种类型**分组
- **可支援工序**：当前人数 > 需要人数（存在冗余人力）
- **需支援工序**：当前人数 < 需要人数
- 在相同工种内，从富余工序向缺人工序派遣人员
- 生成支援指令：「工序 A 派 X 人 → 工序 B（同工种）」
- **支援时段（每天几点去支援）**：富余工序全员完成本工序当日份额后，剩余人力方可去支援；系统把该"完工偏移"映射到真实作息（跳过段间休息）得到起始时刻 `supportStart`，结束 `supportEnd` = 当日最后一班结束时间
- **20% 弹性缓冲**：`buffer = 完工偏移 × 20%`，在支援卡片中提示"实际到岗时间误差控制在 20% 以内"

> 示例：前车架总成组对（组对工 冗余1人）在 `10:51` 完成本职后可去支援后车架总成组对，支援时段 `10:51-19:00`（缓冲 ≈ 29 min）。

### 改善前/改善后对比
- 在「数据录入」页为每个工序填写「改善后单件时间 / 改善后人数」（留空=不变）
- 系统分别对改善前、改善后计算上述全部指标并逐项对比，标注改善方向（✔ 更优 / 需关注）

## 快速开始

### 方式一：Android Studio 打开（推荐本地开发）

1. 用 Android Studio 打开 `EfficiencyWarRoom` 目录。
2. 首次打开时，IDE 会自动下载 Gradle wrapper 和依赖。
3. 连接手机/平板（开启 USB 调试），点击 **Run** 即可安装。

### 方式二：Gradle 命令行构建

```bash
# 进入项目目录
cd EfficiencyWarRoom

# 生成 wrapper（若缺失）
gradle wrapper --gradle-version 8.9

# 构建 Debug APK
./gradlew assembleDebug
```

构建产物位于 `app/build/outputs/apk/debug/app-debug.apk`。

### 方式三：GitHub Actions CI

仓库已配置 `.github/workflows/build-apk.yml`。推送代码到 `main` 分支后，Actions 会自动构建 APK 并上传到 artifact `EfficiencyWarRoom-apk`。

## 输出示例

### 作战沙盘
- 产线节拍、平衡率、瓶颈工序、预计日产量 KPI
- 各工序节拍 vs 客户节拍柱状图
- 各工序负荷率（绿/黄/红）
- 人员差异图（冗余/不足）

### 调度大屏（生产调度看板）
- 顶部「日产台数」场景选择器：直接点选 1/2/3/5/10/20/50/80 台/日，或步进微调
- 切换后实时刷新：客户节拍、需要人数、最少人数、瓶颈工序
- 下方为 Excel 式作战图矩阵 + 自动支援方案卡片
- 宽屏（≥600dp）自动显示左侧导航栏，便于车间大屏投影

### 作战图 / 改善对比
- 横向滚动的 Excel 式矩阵（作战图）
- 协作流程图行用箭头直观显示「A 工序派 X 人支援 B 工序」
- 单人单台时间 / N 台时间 / 日可用时间 / 差异时间 / 需要人数 / 人员配置状态
- 改善对比页：改善前 vs 改善后 关键指标卡（绿=更优）+ 工序级时间/人数对比表

### 布局调整
- 高负荷工序靠近布置建议
- 物流动线缩减建议
- 打磨工序集中/隔离建议

### 人员调配
- 当前 vs 理想人数
- 每工序差异与具体行动（增员/减员/支援）

### 提升方案
- 瓶颈工序增员
- 冗余人员再分配
- 合并短作业工序
- 平衡率目标与预计产能提升
